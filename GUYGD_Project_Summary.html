📌 Project Overview

The GUYGD website is a full-stack web platform built for the Gbeh-lay United Youths for Growth and Development organization. It serves as the official digital presence for the organization — enabling youth registration, scholarship applications, event management, news publishing, gallery uploads, donation tracking, and administrative oversight through a secure dashboard.

⚙️ Technology Stack

🖥️ Frontend

  • HTML5, CSS3
  • Vanilla JavaScript
  • Responsive design
  • Dark mode support
  • CSS animations

🔧 Backend

  • Node.js v18+
  • Express.js
  • REST API
  • JWT Authentication
  • Bcrypt password hashing

🗄️ Infrastructure

  • PostgreSQL (Railway)
  • Railway hosting
  • GitHub (version control)
  • Nodemailer (email)
  • Multer (file uploads)

Client (Frontend) — client/

  • src/pages/ — All HTML pages

  • index.js — App entry, migrate, seed, listen

  • /dashboard/member — Member portal: profile, scholarship applications, membership card
  • /dashboard/admin-login — Dedicated admin login page

Authentication Flow

  • User logs in → JWT token issued
  • Token stored in localStorage
  • Every API call sends Authorization: Bearer <token>
  • authMiddleware verifies token on protected routes
  • roleMiddleware checks user role for admin routes
🚀 Deployment & Hosting

Railway Platform

  • Auto-deploys on every push to main branch
  • Builder: Railpack (detects Node.js automatically)
  • Start command: npm start → node server/index.js
  • Region: US West (sfo)
  • 1 Replica, restart on failure (max 10 retries)
  • PostgreSQL database provisioned on Railway

Environment Variables (Railway)

  • DATABASE_URL — PostgreSQL connection string
  • JWT_SECRET — Secret key for token signing
  • NODE_ENV — production
  • CLIENT_URL — Live site URL for CORS
  • EMAIL_USER — Gmail address for Nodemailer
  • EMAIL_PASS — Gmail app password
  • PORT — Assigned automatically by Railway
Deploy workflow: git add . → git commit -m "message" → git push origin main → Railway detects push → Railpack builds → New container starts → migrate() runs → Server listens → Live ✅
